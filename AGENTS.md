# Project Architecture & Guidelines

## Core Principles
1. **Target Platform**: Poki (WebGL/HTML5). Optimized for performance, low memory footprint, and high responsiveness.
2. **Physics**: NO Box2D physical components (`collisionobject`). All collision and distance calculations use pure Lua circle mathematics:
   $$(\Delta x)^2 + (\Delta y)^2 < R^2$$
3. **Communication**: Minimize Defold `msg.post`. All business and simulation logic resides in modules (`main/modules/*.lua` and `modules/*.lua`) with direct Lua function calls.
4. **Poki SDK**:
   - `poki_sdk.gameplay_start()` is called strictly on the player's first input/click.
   - `poki_sdk.gameplay_stop()` is called when a level finishes (victory or defeat).
5. **Camera & Adaptability**: Built with `defold-orthographic` for universal mobile & desktop screen scaling.
6. **UI & Localization**: Built strictly with Druid. All user-facing strings are resolved through `modules/i18n.lua` (supporting English `en`, Portuguese `pt`, Russian `ru`, Turkish `tr`). UI prioritizes clear icons and numbers over long text. `main/gui/main.gui` is generated by `tools/gen_gui.js`; edit the generator, not the .gui.

## Directory Structure
- `entities/` (and `main/entities/`): All game objects needed for the game. Each entity has a dedicated subfolder containing the script and gameobject of the exact same name (e.g. `melee/melee.go`, `melee/melee.script`).
  - Units (`archer`, `melee`) are visual containers only (sprites, tier markers) with NO logic in `update()`.
  - `bunch_controller`: Controls squad formation, movement, and combat in a unified array.
  - `battle_manager`: Manages battle flow, squad spawning, level progression.
  - `projectile_manager`: Renders the arrow pool simulated in `modules/projectiles.lua` (arcing flight, no `go.delete()`).
  - `drag_manager`: Controls drag & drop grid merging ($A + A \rightarrow B$).
- `modules/` (and `main/modules/`): Pure Lua modules containing all game logic, economy, level designs, grid data, and tutorial state.
- `assets/` (and `main/assets/`): Sprites, atlases, and visual assets.
- `gui/` (and `main/gui/`): UI built with Druid.

## Game Mechanics
- **Grids**: $4 \times 4$ Player field at the bottom and $4 \times 4$ Enemy field at the top; a thin gap between them holds the power comparison / trash bin.
- **Tiers**: every merge multiplies squad HP and damage by 2.2 (`config.TIER_GROWTH`), so a merge is always an upgrade. Warrior counts per tier form readable shapes: 3, 5, 7, 9, 12, 16, 20, 25, 30, 36, 42 (`config.UNIT_COUNTS`).
- **Economy**: shop sells tier `best_tier - 3`; price grows 18% per purchase inside a level; kill coins are kept on defeat.
- **Progression**: procedural 300-level campaign on a two-level sawtooth curve (`levels.lua`), endless afterwards. Tune only with `tools/balance_sim.lua`.
- **Flow**: no victory/defeat screens: a win starts the next level, a loss restarts the level (`battle_state.finish_battle`).
- **Monetization**: rewarded free squad on the buy buttons when broke; interstitials only at the post-battle transition (`poki.level_break`).
- **Tutorial (Level 1)**: Hand FSM: Buy (melee) -> Merge -> Fight.
- **Full design, balance tables, tools and change log**: [docs/KNOWLEDGE_BASE.md](docs/KNOWLEDGE_BASE.md).

## Mandatory Rule for Agents
Before making changes to this codebase, all AI agents MUST first inspect this file (`AGENTS.md`) and [docs/KNOWLEDGE_BASE.md](docs/KNOWLEDGE_BASE.md), record every gameplay/balance/UI/monetization change in the knowledge base change log, and keep all modifications strictly aligned with the directory structure, Lua module architecture, Druid GUI standards, and Poki SDK requirements outlined above.
